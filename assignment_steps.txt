MODEL GRAPH VISUALIZATION WITH TRANSFORMATION PASSES - STEP-BY-STEP PLAN
=========================================================================

Goal: Build a Python library + CLI that loads an OpenVINO model, converts it to a
framework-independent graph, applies configurable transformation passes, and
renders the result to SVG (Graphviz "dot", top-to-bottom). Deliver as a GitHub repo.

Pipeline:  Model Loading -> Graph Construction -> Graph Transformation -> Graph Rendering

Legend:  [x] done   [~] partially done / draft   [ ] not started
Status as of 2026-10-13: 27 tests passing (+ test_renderer.py), coverage 76%
(graph 96%, parser 94%, renderer 89%, transformation 82%).
!! Uncommitted: renderer.py (proxy copies, empty-field fix), transformation.py +
   graph.py (ProxyPass, proxy_output), main.py, pyproject.toml, tests/test_renderer.py.

STEP 1 - Intermediate Graph Representation (section 3.2)
-------------------------------------------------------------------------
[x] Node: unique id (separate from name), name, op type, attributes dict,
    visualization metadata (NodeMetadata: border_color, hidden_inputs).
[x] Edge: src node id + output port, dst node id + input port,
    tensor shape (optional, supports dynamic/partial dims like "?" or ranges),
    dtype (optional).
[~] Graph container with efficient indexes (avoid full scans):
      [x] nodes by id (dict)
      [x] incoming edges per node, outgoing edges per node (_in / _out)
      [ ] name -> list of node ids (names may be duplicated!)
[~] Operations: [x] add_node, add_edge, remove_node (also removes its edges),
    remove_edge, in/out edges, in/out degree;
    [ ] lookup by name; [ ] rename outcoming_edges -> outgoing_edges,
    return list copies + return type hints.
[x] topological_sort (Kahn, iterative, raises on cycle).
    [ ] optional: heapq by insertion index for a "deep" order
        (FIFO Kahn gives a level-by-level order).
[~] Must handle: multiple inputs/outputs, multiple edges between same pair of
    nodes, duplicate names, dynamic shapes, missing metadata, Parameter/Result ops.
    (supported by design; duplicate names + dynamic shape strings covered
     only indirectly by pass tests)
[x] Keep the graph valid after modifications (no dangling edges).
[ ] Optional: a validate() method used by tests.
[x] itertools.count replaced with int counters; add_node(node, node_id=None)
    accepts an explicit id (auto ids now start at 1; counter = last used id,
    max() keeps auto ids above manual ones).
    [ ] duplicate id raises KeyError -> ValueError is more fitting;
    [ ] tests for explicit id / duplicate id;
    note: OpenVINO get_instance_id() is process-global and unstable between
    loads, XML layer ids are not exposed by read_model - keep own ids.
